# Contract-First OpenAPI

## Source of Truth

- The OpenAPI document is written first in `openapi/openapi.yaml`.
- Do not use SpringDoc annotations to generate the API contract from controllers.
- Controllers implement interfaces generated by the OpenAPI Generator Gradle plugin.
- Generated code is build output. Do not edit generated interfaces or models by hand.
- Changes to endpoints, schemas, response codes, security, and examples start in the OpenAPI spec.

## Gradle Generator

Use the OpenAPI Generator Gradle plugin with the Spring generator:

```kotlin
plugins {
  id("org.openapi.generator") version "7.22.0"
}

openApiGenerate {
  generatorName.set("spring")
  inputSpec.set(layout.projectDirectory.file("openapi/openapi.yaml").asFile.absolutePath)
  outputDir.set(layout.buildDirectory.dir("generated/openapi").get().asFile.absolutePath)
  apiPackage.set("com.demo.skills.api")
  modelPackage.set("com.demo.skills.api.model")
  configOptions.set(
      mapOf(
          "interfaceOnly" to "true",
          "useSpringBoot3" to "true",
          "useTags" to "true",
          "annotationLibrary" to "none",
          "documentationProvider" to "none",
          "openApiNullable" to "false"))
}
```

`compileJava` must depend on `openApiGenerate`, and `check` must depend on `openApiValidate`.

## Spec Structure

- One file at `openapi/openapi.yaml` until the contract becomes large enough to justify splitting.
- All endpoints live under `/api/v1` through the server URL or path prefix.
- Every operation has a stable `operationId`.
- Every operation has tags, summary, security, and complete responses.
- Every request and response schema is defined under `components.schemas`.
- Error responses use RFC 9457 Problem Details.

## Controller Pattern

- Implement generated interfaces in thin Spring controllers.
- Put business logic in services.
- Do not duplicate request mappings by hand when the generated interface already declares them.
- If a controller method signature needs to change, change `openapi/openapi.yaml` and regenerate.

```java
@RestController
@RequiredArgsConstructor
public class OrderController implements OrdersApi {

  private final OrderService orderService;

  @Override
  public ResponseEntity<OrderResponse> getOrder(final UUID orderId) {
    return ResponseEntity.ok(orderService.getOrder(orderId));
  }
}
```

## Schema Rules

- Prefer explicit object schemas with `additionalProperties: false`.
- Mark required fields in `required`.
- Use `format: uuid`, `format: date-time`, and numeric constraints where appropriate.
- Use enums for stable bounded values.
- Use examples for externally visible request and response fields.
- Keep internal persistence fields out of public schemas unless clients genuinely need them.

## Error Contract

- Define a reusable `ProblemDetail` schema compatible with RFC 9457.
- Every operation declares expected `4xx` and `5xx` responses.
- Use `application/problem+json` for error response content.
- Load `spring-exceptions-problemdetail` when implementing handlers.

## Review Checklist

- [ ] Spec changed before controller implementation.
- [ ] `operationId` is stable and unique.
- [ ] Generated interfaces compile.
- [ ] Controllers implement generated interfaces.
- [ ] No SpringDoc dependency or annotations are introduced as the contract source.
- [ ] `openApiValidate` passes.
